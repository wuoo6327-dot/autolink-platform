# 安全候选发布范围（未部署）

基于 main `96f1f34`，分支 `codex/security-release-candidate`。本候选可独立审查，但“已经拆出”不等于“允许立即生产部署”。

## 包含

- 平台所有者/最后一个平台管理员账号关闭保护、原子检查、停用/关闭账号不发新 session。
- 私有车图按数据库当前账号和平台所有者配置授权。
- Cookie 会话的关闭入口、Cookie 清除、旧 Bearer 兼容；真实业务和历史记录保留。
- Cookie/隐私/账号关闭文案的技术说明纠正。
- Requests 2.34.2、Docker 健康检查、Gitleaks/Trivy 检查与对应回归测试。

## 不包含

- 新商家自动启用及正式协议门槛；仍保持 main 的旧商家流程。没有借此宣布草稿协议可用于正式运营。
- 买家/商家能力共存、GET 业务状态只读、车型 SSR/九语言 Sitemap；这些在完整候选中。
- 会员支付、真实供应商或库存、生产配置/数据库/文件。

## 测试边界

Linux arm64 Docker 后端全套 193 项：188 通过、5 个既有社交草稿跳过、0 失败。第一次全套出现一个旧 fixture 在撤销账号后申请新 session 的错误，已改为撤销前发 session，完整重跑通过。未放宽账号安全断言。

P0 回归 9 项已通过；另有 Requests 和 Google-auth 真实库通过本地合成证书的签名/错误 audience 测试。账号关闭前端范围 16 项通过。合成账号和车源仅用于临时测试库，不是实际业务。

源码扫描通过不代表实际镜像通过。Python/Debian 镜像扫描有 44 条 HIGH 匹配（8 个 CVE）；未进行破坏性验证。需按第二轮报告评估基础镜像和正式服务器架构。

## 合并纪律

main 保持不动；PR 保持草稿，人工确认测试证据、镜像风险和回滚方案后才能决定发布。仓库维持私有；当前套餐无法强制保护不作为开发阻碍。旧 CLI 账号仍用于当前授权上传，完成账号接管后再由所有者移除它的写权限。

实际 Caddy 官方 v2.11.7 仍有 4 条 HIGH 匹配（3 个 CVE），详见 `ROUND2_IMAGE_FINDINGS.md`。不得仅更新浮动标签就宣称已修复。

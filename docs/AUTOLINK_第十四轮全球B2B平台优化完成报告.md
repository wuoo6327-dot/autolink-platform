## 2. 本轮实际改动

| 模块 | 变更 |
| --- | --- |
| 车型详情到采购需求 | 服务端初始 HTML 和交互页均增加车型直达采购需求的入口，携带真实车型 ID 与语言；供应商车源入口单独保留。 |
| 买家登录与表单 | 未登录时保存 `returnTo`；从登录切换到注册继续保留所选车型。选中车型后从当前公开目录带入品牌、年份和动力；加入目的港、配置等输入。草稿在同一浏览器会话中按账号暂存 24 小时，成功提交及退出登录时清除；共享同意不暂存。 |
| 需求提交与跟踪 | 后端固定车型的目录事实并保存所需配置；同一车型的重复请求受现有防重规则拦截，不同车型不会误判。成功显示真实 `REQ-` 编号，买家中心可查；状态操作防连续点击并提示结果。 |
| 车型查找 | 车型参考目录加入品牌、年份、能源类型筛选；支持已审核英文名称匹配，组合动力可按单个类型筛选。买家目录分别提供采购需求与已审核车源入口，空结果保持明确提示。 |
| 管理员跟进 | 复用既有后台、询盘表及审计表，增加真实采购需求和供应商询盘列表、买家关联与内部跟进备注。后台每次读取/写入均复核管理员身份；备注不自动通知买家，也不改变询盘状态。 |
| 商家与车源 | 没有修改商家准入、审核或公开规则。隔离浏览器检查商家申请页可显示草稿状态、待补资料和公开条件；未审核车源仍不进入公开列表。 |

主要代码：`auth/app.py`、`auth/buyer_service.py`、`auth/trade_service.py`、`auth/seo_service.py`、`site/buyer/app.js`、`site/trade/app.js`、`site/trade/model-directory.mjs`、`site/trade/directory-locales.js`、`site/trade/model-reference.css`、`site/admin/app.js` 及对应静态入口版本号。新增/扩展测试：`auth/test_buying_requests.py`、`auth/test_current_catalog_seo.py`、`tests/test_model_directory.mjs`、`tests/round14_browser_qa.cjs`。首页主脚本、首页视觉、会员及支付实现没有修改。

## 4. 发布状态、阻断与后续步骤

代码候选提交为 `ecee142`，草稿 [PR #15](https://github.com/wuoo6327-dot/autolink-platform/pull/15) 以 Round 12 分支为基底，未合并 `main`。本轮 **未部署生产、未执行 30 分钟上线监控、未改动生产数据库、未提交 Google Sitemap 或索引申请**。

已从本机 SSH `known_hosts` 找到阿里云入口 `47.242.74.16:22`，网络可达；但 `admin` 账号只接受公钥，而这台 Mac 的 SSH Agent 无身份，常用目录也没有对应私钥。浏览器 Workbench 不满足连续可控发布窗口。此条件下无法核验当前生产镜像与运行配置、制作切换前最新一致性备份、验证上传/证书卷恢复并执行原生 AMD64 与回滚演练，因此 **不能启动生产切换**。之前轮次的备份不能冒充本轮最新备份。

恢复安全连接后，按现有 Runbook 在阿里云原生 AMD64 隔离环境复核本候选和生产目录；读取实际 DB 路径，制作最新 SQLite 一致性快照及上传、配置、证书和旧镜像备份，隔离恢复并演练回滚。仅在全部门槛通过且生产目录仍一致时，先 Auth 后 Web 切换，验证买家/商家/管理员及 SEO，连续监控至少 30 分钟。若目录变化或关键测试失败，重新审核并保持生产现状。

下一阶段运营重点是完善真实已审核供应资源和买家询盘响应时效，持续在 Search Console 观察英文车型曝光与已收录数量，并区分访问、注册和有效采购询盘；支付开发继续独立搁置。

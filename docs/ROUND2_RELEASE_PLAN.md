## 生产部署及回滚方案（待确认，未执行）

1. 锁定批准的 commit 和服务器架构镜像 digest，人工审阅 PR；不得仅凭绿色源码检查批准全部业务改动。
2. 生产变更前重新备份一致性的 SQLite 数据库（含 WAL 一致性）、私有图片/附件、代码、配置和当前镜像摘要；在隔离目录验证恢复，秘密不入 GitHub。

4. 先用同架构预发布验证启动、健康、匿名/所有者权限、历史记录条数和抽样历史 ID；再由所有者决定生产发布窗口。简单单服务器 Compose 不自动具备无损灰度，需确认代理/端口切换方案。

6. 旧镜像包含已知安全问题，回滚可能重新暴露 P0；必要时停用风险入口并维护模式，不能把旧镜像当作安全兜底。上述生产动作都需要所有者最终确认。
